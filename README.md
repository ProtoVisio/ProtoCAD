# ProtoCAD

Открытая часть ПРОТО: параметрическое моделирование на ядре Open CASCADE.
Оформление документов по ЕСКД и остальная инженерная среда живут отдельно и
закрыты; здесь — код геометрии, эскиза, сборки и просмотра.

Лицензия — **LGPL-2.1-or-later**, см. [LICENSE](LICENSE). Сторонние
компоненты и их лицензии разобраны в [THIRD_PARTY.md](THIRD_PARTY.md) и
[SBOM.md](SBOM.md).

## Установка и запуск

Нужно две вещи: **Python 3.12+** (64-битный, python.org) и — для окна
детали — **FreeCAD 1.1** (freecad.org, обычный установщик). FreeCAD работает
у ProtoCAD невидимым движком операций в отдельном процессе со своим Python;
его окно не открывается. Сборка, подготовка к расчёту, подготовка прибора и
просмотрщик работают и без FreeCAD.

Windows, командная строка в папке репозитория:

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install -r requirements.txt
python -m protocad.doctor
```

`protocad.doctor` ничего не ставит: проверяет Python, пакеты, ищет FreeCAD,
поднимает движок и пишет, какие окна будут работать и чего не хватает.
FreeCAD ищется в `C:\Program Files\FreeCAD 1.1` (и 1.0), в папке `FreeCAD\`
рядом с репозиторием и в PATH; другое место — переменной окружения:

```bat
set PROTOCAD_FREECAD=D:\Программы\FreeCAD 1.1
```

Linux: FreeCAD из AppImage распаковывается командой
`./FreeCAD_1.1.3-Linux-x86_64-py311.AppImage --appimage-extract`, и
`PROTOCAD_FREECAD` указывает на получившуюся папку `squashfs-root`.

Окна:

| Что | Команда |
|---|---|
| деталь (нужен FreeCAD) | `python protocad_app\app.py` |
| сборка | `python protocad_asm\app.py` |
| подготовка прибора к тепловому расчёту | `python protocad_device\app.py [прибор.step]` |
| подготовка геометрии к расчёту | `python protocad_prep\app.py [деталь.step]` |
| просмотрщик | `python protocad_viewer\app.py файл.prcadAsm` |

Проверки: `python -m pip install pytest`, затем
`python -m pytest asm_tests prep_tests device_tests gl_tests` (тесты окон
пропускаются без дисплея).

## Сборка

Окно: `python protocad_asm/app.py [узел.prcadAsm | деталь.step …]`, из
конструирования — «Файл → Новая сборка» / «Открыть сборку…».

* **Вставить** — STEP, IGES, BREP, сборка или деталь ProtoCAD. STEP читается
  со структурой: сборка остаётся сборкой, позиционные обозначения (R12,
  DD3) — именами вхождений, одинаковые детали — одним определением на все
  вхождения. Первое вставленное закрепляется.
* **Сопряжения** — совпадение и расстояние (две плоские грани), соосность
  (две цилиндрические). Команда → щелчок по грани одной детали → по грани
  другой → деталь встаёт сразу; «Развернуть», расстояние, «Применить» или
  «Отмена» — на панели. Сопряжения, которые нельзя выполнить вместе,
  называются вслух, а не «примерно» выполняются.
* **Закрепить**, **Переместить**, **Удалить**, отмена — Ctrl+Z.
* **Спецификация** — состав по разделам, сохраняется в CSV.
* **Экспорт STEP** — сборкой, с именами: расчётная система получает «R12» и
  «Корпус», а не «Solid1».

Показ: вся сборка — один буфер видеопамяти, разбивка каждого определения на
треугольники считается один раз за жизнь окна. Сдвиг детали пересобирает
буфер из готовых треугольников, выбор и подсветка меняют только маленький
буфер признаков — геометрия в видеопамяти не перезаливается.

Проверки: `python -m pytest asm_tests` (тест окна — под `xvfb-run` или с
дисплеем).

## Прибор: подготовка к тепловому расчёту

Окно: `python protocad_device/app.py [прибор.step | прибор.prcadAsm]`, из
конструирования — «Файл → Подготовка прибора к тепловому расчёту…». Без
файла открывается образец с нарочно оставленными ошибками модели.

1. **Разбор.** STEP раскладывается на расчётные единицы: компонент — целиком,
   с выводами; плата — узел с тонкой пластиной и деталями на ней; крепёж — по
   имени (ГОСТ/ISO/DIN, винт, гайка, шайба) и по форме; корпус — по имени и
   размеру. У каждой единицы записано, почему она так названа; окно
   «Разбор прибора» показывает это и даёт поменять: отклонить или указать
   плату, сменить роль, правило обозначений (ГОСТ 2.710 или западное).
2. **Дерево.** По видам (плата → основание, R — Резисторы, C — …; корпус;
   крепёж; прочее) или по расчётным случаям. Роль, вид, материал, случай —
   из меню дерева, для одной единицы или сразу для выбранных.
3. **Расчётные случаи.** Полукомплекты платы с подряд идущими номерами
   (R1–R12 и R13–R24) разделяются по составу половин, общее (C17, XS1) — в
   оба случая. Отнесение по диапазонам: «R1–R20, C1…C15, DD1».
4. **Проверка.** Контакты с площадью (плоские грани навстречу, вал в
   отверстии), зазоры до 0,5 мм (компонент висит над платой), пересечения
   (резьба крепежа отмечена отдельно), детали без единого контакта, группы
   без связи с корпусом.
5. **Тепловые контакты.** Слой в контакте — паста, прокладка, клей, припой,
   воздух, сухой контакт — с λ и толщиной: r = t/λ (м²·К/Вт, Contact
   Resistance в SOLIDWORKS Flow Simulation), h = λ/t (Вт/(м²·К), Thermal
   Conductance в Ansys), R = r/S (К/Вт). Выгрузка — CSV для Excel и JSON.
6. **Упрощение.** Отверстия до заданного диаметра, компоненты — брусками по
   габариту (стоят на плате, выводы под платой отрезаны), исключение мелочи
   и крепежа. Правится определение — для всех вхождений сразу; всё
   отменяется.
7. **STEP для расчёта** — по видам (Корпус / плата с группами по типам ЭРИ /
   Крепёж / Прочее) или как пришло, без исключённых деталей.

Показ: вся геометрия прибора — один буфер видеопамяти; раскраска по видам,
типам ЭРИ, случаям и замечаниям, выбор и скрытие меняют только буфер
признаков. Плата на 1057 компонентов: разбор 0,4 с, проверка контактов 3,3 с.

Проверки: `python -m pytest device_tests` (тест окна — под `xvfb-run`).

## Подготовка к расчёту

Путь модели от CAD до расчётной системы:

```
STEP / IGES / BREP / деталь или сборка ProtoCAD
  → проверить → исправить → упростить (отверстия, скругления,
    мелкие грани) → группы граней и тел → STEP с именами тел
```

На выходе — геометрия, а не сетка: сетку строит та система, куда модель
уходит (SolidWorks Flow Simulation, Ansys и любая другая, читающая STEP).

Окно: `python protocad_prep/app.py [изделие.step]`, из конструирования —
«Файл → Подготовка к расчёту…». Грани выбираются щелчком (Ctrl — добавить).

Всё, что сделано в окне, сохраняется **рецептом** и повторяется на новой
версии изделия одной командой — без окна:

```bash
python -m protocad.prep check  изделие.step
python -m protocad.prep holes  изделие.step --diameter 8
python -m protocad.prep run    изделие.prep.json --source изделие-v2.step
```

Группы в рецепте лучше задавать правилом, а не выбором мышью: «плоская грань
с нормалью вниз, самая нижняя» найдётся и в следующей версии. Правила
описаны в `protocad/prep/select.py`, формат рецепта — в
`protocad/prep/recipe.py`.

Проверки: `python -m pytest prep_tests` (тест окна — под `xvfb-run` или с
дисплеем).

## Чего в этом репозитории нет

Проект прошёл исследовательскую фазу: два измерительных прогона, от которых
зависела архитектура. Задание, результаты замеров и оркестраторы прогонов
остались во внутреннем дереве — они описывают, **как принималось решение**, а
не то, как работает код.

Поэтому строки документации в коде ссылаются на документы вроде
`docs/08_ENGINE_BACKEND.md`, которых здесь нет. Ссылки оставлены как есть:
переписывать их задним числом значило бы потерять след, откуда правило взялось.

Там же остались проверки на втором решателе (`py-slvs`, GPL-3): они намеренно
изолированы от рабочего кода и в поставку не входят — см. THIRD_PARTY.md.
